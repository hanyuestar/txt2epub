# 编码与兼容性

## 编码检测流程

`read_book_text` 按以下顺序确定 TXT 编码，尽可能正确解码中文内容：

1. 先尝试 **UTF-8（含 BOM，`utf-8-sig`）**；
2. 失败后做**自动检测并重新排序**：对候选编码按「解码后 CJK 汉字占比 + 中文编码微偏好」重排，**仅当中文编码（gb18030 / gbk / big5）胜出才采纳检测**；
3. 否则走确定性兜底：`gb18030 → gbk → big5`；
4. 最后以 `gbk(errors="replace")` 保底，避免个别非法字节导致整文件失败。

如仍不准确，可用 CLI `--encoding` 手动指定（如 `--encoding gbk`）绕过自动检测。

## v1.0.0 的 GBK / GB18030 乱码修复

**问题**：早期版本直接采用 `charset_normalizer.from_bytes(...).best()`，而 `.best()` 的排序常把与 GBK 字节范围高度重叠的**韩文 / 日文编码（cp949、cp932）排在 gb18030 之前**，导致简体中文 TXT 被解成韩文乱码（如 `뒤1覽 코휭` 而非 `第1章 内容`），同时 Big5 繁体不受影响。

**修复**（commit `026b339`）：新增「中文编码优先」重排逻辑——按 CJK 汉字占比对检测候选重新排序，仅当中文编码胜出才采纳自动检测，否则走确定性兜底。修复后相关兼容性测试由失败转为通过，Big5 用例不回归。

> 如果你仍遇到个别文件乱码，优先用 CLI `--encoding` 显式指定该文件真实编码。

## 文本清洗

- `normalize_book_text` 将抓取文本中的 `<p> <br> <div> <h1-6> <li>` 等块级标签转为换行；
- 自动 `html.unescape` 解码 `&amp;` 等实体；
- 过滤 EPUB / XHTML 不允许的无效 XML 控制字符，避免生成损坏的 EPUB。

## 已知限制

- GUI v1 **不暴露**编码、封面、标题等高级参数；
- 不支持中途中止；
- 文件夹扫描仅顶层（不递归）；
- 繁体中文（Big5）同样支持，但自动检测对繁体的判定依赖字节特征，必要时用 `--encoding big5` 指定。
